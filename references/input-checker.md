# 输入识别模型 — 待评估Skill的8类内容检查

> 每类内容定义：检查目标、判断问题、可提取证据

## Skill类型识别（评审前置）

> 不同类型的Skill检查重点不同，先识别类型再差异化检查

### 4类Skill识别

| 类型 | 识别信号 | 核心检查重点 |
|------|----------|-------------|
| 工具调用型 | 有 scripts/ 目录，脚本驱动 | 脚本质量、错误处理、退出码、参数化 |
| 知识增强型 | 有 references/ 目录，引用驱动 | 引用策略、证据标注、冲突处理 |
| 模板驱动型 | 有 templates/ 或 assets/ 目录 | 占位符规范、结构保护、输出校验 |
| 编排调度型 | 有 workflow/ 或 roles/ 目录 | 阶段定义、输入输出契约、中断回滚 |

### 识别流程

```
扫描Skill目录结构
    │
    ├── 有 scripts/ → 工具调用型（重点查脚本）
    ├── 有 references/ → 知识增强型（重点查引用）
    ├── 有 templates/ 或 assets/ → 模板驱动型（重点查模板）
    ├── 有 workflow/ 或 roles/ → 编排调度型（重点查流程）
    └── 以上都有 → 混合型（按主要约束手段归类）
```

## 1. SKILL说明

### 检查目标

确认Skill的身份信息完整，Agent能正确识别和触发。

### 检查项

| 检查项 | 判断标准 | 问题等级 |
|--------|----------|----------|
| frontmatter存在 | YAML `---` 包裹的头部存在 | P0 |
| name字段 | frontmatter中有name字段，且值唯一 | P0 |
| description字段 | frontmatter中有description字段，且非空 | P0 |
| description_zh | 有中文描述 | P1 |
| 触发词定义 | SKILL.md中明确写了触发词或使用方式 | P1 |
| 核心描述 | 开头1-2句话说清"帮谁做什么省什么" | P1 |
| 使用场景 | 有"使用场景"或"适合/不适合"段落 | P1 |
| 能力边界 | 有"不做什么"或"边界"声明 | P2 |

### 可提取证据

- frontmatter原始内容（截图级）
- name和description的具体值
- 触发词列表
- 使用场景段落文本

---

## 2. README说明

### 检查目标

确认项目有独立说明文档，方便用户快速了解。

### 检查项

| 检查项 | 判断标准 | 问题等级 |
|--------|----------|----------|
| README.md存在 | 根目录有README.md | P2 |
| 安装指引 | 有安装步骤说明 | P2 |
| 功能概述 | 有功能概述 | P2 |
| 与SKILL.md不重复 | README不简单复制SKILL.md内容 | P2 |

### 可提取证据

- README.md是否存在
- README.md的章节标题列表
- 与SKILL.md的重复度

---

## 3. 使用示例

### 检查目标

确认用户能通过示例快速上手，不需要读完整文档。

### 检查项

| 检查项 | 判断标准 | 问题等级 |
|--------|----------|----------|
| 示例数量 | 至少2个使用示例 | P1 |
| 示例覆盖 | 覆盖主要使用场景 | P1 |
| 可复现性 | 示例有具体输入和预期输出 | P2 |
| 触发词示例 | 示例中展示了触发方式 | P1 |

### 可提取证据

- 示例数量和内容
- 是否有输入/输出对照
- 触发方式是否明确

---

## 4. 脚本能力

### 检查目标

确认脚本可靠、安全、不会阻塞Agent。

### 检查项

| 检查项 | 判断标准 | 问题等级 |
|--------|----------|----------|
| 无交互阻塞 | 脚本不含input()、readline等交互语句 | P0 |
| 错误处理 | 有try-catch或等价错误处理 | P1 |
| 退出码 | 脚本有退出码（0成功/非0失败） | P1 |
| 无硬编码路径 | 不含用户特定路径（如/home/xxx） | P1 |
| 无敏感信息 | 不含API Key、密码等敏感信息 | P0 |
| 参数化 | 关键配置通过参数传入，非硬编码 | P2 |

### 可提取证据

- 脚本文件列表
- 是否包含input()等阻塞语句
- 是否有try-catch
- 退出码定义
- 是否包含硬编码路径或敏感信息

---

## 5. 依赖说明

### 检查目标

确认用户能正确安装所有依赖，不会因缺少依赖而失败。

### 检查项

| 检查项 | 判断标准 | 问题等级 |
|--------|----------|----------|
| 依赖清单 | 有requirements.txt或package.json | P1 |
| 安装方式 | 说明了如何安装依赖 | P1 |
| 版本约束 | 关键依赖有版本约束 | P2 |
| 环境要求 | 说明了Python/Node版本要求 | P2 |

### 可提取证据

- 依赖文件是否存在
- 依赖列表内容
- 安装说明文本

---

## 6. 运行方式

### 检查目标

确认用户知道怎么触发和运行Skill。

### 检查项

| 检查项 | 判断标准 | 问题等级 |
|--------|----------|----------|
| 触发路径 | 说明了自然语言触发方式 | P1 |
| 参数说明 | 说明了输入参数 | P1 |
| 前置条件 | 说明了运行前需要什么 | P2 |
| 命令行方式 | 如有脚本，说明了命令行运行方式 | P2 |

### 可提取证据

- 触发词列表
- 参数说明段落
- 前置条件说明

---

## 7. 输出样例

### 检查目标

确认用户知道会得到什么结果。

### 检查项

| 检查项 | 判断标准 | 问题等级 |
|--------|----------|----------|
| 输出格式 | 说明了输出格式 | P1 |
| 输出示例 | 有实际输出样例 | P1 |
| 可读性 | 输出格式清晰可读 | P2 |
| 结构化 | 输出是结构化的（非大段文字） | P2 |

### 可提取证据

- 输出格式说明文本
- 输出示例内容
- 输出结构化程度

---

## 8. 边界声明

### 检查目标

确认Skill明确了自己的能力边界，不会误导用户。

### 检查项

| 检查项 | 判断标准 | 问题等级 |
|--------|----------|----------|
| 不做什么 | 有"不做什么"或"不适合"段落 | P1 |
| 安全约束 | 说明了安全相关约束 | P2 |
| 已知限制 | 说明了已知限制 | P2 |
| 适用范围 | 说明了适用范围 | P2 |

### 可提取证据

- "不做什么"段落文本
- 安全约束说明
- 已知限制列表

## 识别流程

```
输入Skill目录
     │
     ├── 1. 读取 SKILL.md → 检查 frontmatter + 触发词 + 核心描述
     ├── 2. 读取 README.md（如存在）→ 检查项目说明
     ├── 3. 扫描示例段落 → 检查使用示例
     ├── 4. 扫描 scripts/ → 检查脚本能力
     ├── 5. 扫描依赖文件 → 检查依赖说明
     ├── 6. 读取运行说明 → 检查运行方式
     ├── 7. 扫描输出段落 → 检查输出样例
     └── 8. 扫描边界段落 → 检查边界声明
           │
           ▼
     输出：8类内容的检查结果
     每个问题 → 转入 evidence-format 生成标准证据
```
