# 会议纪要整理助手

帮职场人从散乱的会议记录中一键提取待办、决策和关键信息，省掉每次会后30分钟手动整理纪要的时间。适合需要频繁开会的项目经理、团队负责人使用。

## 使用场景

### 适合使用此技能的情况:
- 开完会后需要整理纪要，手动整理耗时30分钟+
- 需要从会议记录中提取待办事项并追踪到人
- 需要快速回顾会议决策，避免信息遗漏
- 周会/1on1/评审会等不同类型会议需要不同纪要格式

### 为什么做它

每周至少3次会议，每次手动整理纪要30分钟，一周就是1.5小时。而且经常遗漏待办、决策记录不清晰、下次开会找不到上次结论。

### 做出来之后省掉了什么

- 不用手动从会议记录中逐条提取待办
- 不同会议类型自动适配不同格式
- 待办自动标注负责人和截止日期
- 决策有追溯链，不会"上次说的不算"

### 不适合的情况:
- 非会议内容整理（用通用文本处理）
- 需要实时记录（本Skill是事后整理）
- 音频/视频格式（需先转文字）

## 使用步骤

1. 提供会议记录文本（粘贴即可）
2. Skill自动识别会议类型（周会/1on1/评审会）
3. 按对应模板提取：待办事项（含负责人+截止日）、关键决策、风险预警
4. 输出结构化纪要

### 触发方式

- "整理会议纪要" / "帮我整理纪要" — 完整模式
- "快速整理纪要" — 快速模式（只提取待办和决策）
- "整理1on1纪要" — 指定1on1模板

## 示例

### 示例1：整理项目周会

输入：
```
今天周会讨论了三个事情：
1. 用户反馈登录页面加载慢，张三说这周内优化完，最迟周五
2. 下个版本要不要加暗黑模式，大家投票决定先不加，等Q3再说
3. 李四提到后端API文档已经过期了，需要更新，王五负责下周之前搞定
另外赵六请假了，他的任务暂时由孙七接手
```

输出：
```markdown
# 项目周会纪要

## 基本信息
- 会议类型：周会
- 关键参会人：张三、李四、王五、赵六（请假）、孙七

## 待办事项
| 任务 | 负责人 | 截止时间 | 优先级 |
|------|--------|----------|--------|
| 优化登录页面加载速度 | 张三 | 本周五 | 高 |
| 更新后端API文档 | 王五 | 下周前 | 中 |
| 接手赵六的待办任务 | 孙七 | 待确认 | 待定 |

## 关键决策
1. 暗黑模式暂不加，推迟到Q3

## 风险预警
- 赵六请假，任务交接需确认截止日
```

### 示例2：整理1on1记录

输入：
```
和小明1on1，他说最近工作量太大，想调整一下优先级。他觉得用户调研可以往后推，先集中精力做核心功能。我同意了，核心功能优先。另外他提到想学Rust，我建议他可以用Rust写个小工具练手。下次1on1定在两周后。
```

输出：
```markdown
# 1on1 纪要

## 基本信息
- 会议类型：1on1
- 参与人：小明

## 待办事项
| 任务 | 负责人 | 截止时间 | 优先级 |
|------|--------|----------|--------|
| 调整工作优先级：核心功能优先 | 小明 | 本周 | 高 |
| 用Rust写小工具练手 | 小明 | 自主安排 | 低 |

## 关键决策
1. 用户调研推迟，核心功能优先

## 成长关注
- 学习方向：Rust（建议通过小工具项目实践）

## 下次1on1
- 时间：两周后
```

## 输出格式

根据会议类型自动选择模板：
- **周会模板**：基本信息 + 待办事项 + 关键决策 + 风险预警
- **1on1模板**：基本信息 + 待办事项 + 关键决策 + 成长关注 + 下次安排
- **评审会模板**：基本信息 + 评审结论 + 修改意见 + 待确认项

## 处理逻辑

Skill使用以下Prompt模板处理会议记录：

```
你是一个会议纪要整理助手。请根据以下会议记录，提取结构化纪要。

会议类型：{自动识别或用户指定}
输出模板：{根据会议类型选择}

提取规则：
1. 待办事项必须包含：任务描述、负责人、截止时间（如未提及标注"待确认"）
2. 关键决策必须包含：决策内容、决策依据
3. 风险/关注项单独列出，不混入待办
4. 如有未明确的信息，标注[待确认]而非自行推断

会议记录：
{用户输入}
```

## 与直接Prompt的区别

| 维度 | 直接让AI整理 | 本Skill |
|------|-------------|---------|
| 会议类型识别 | 需要手动指定 | 自动识别 |
| 输出格式 | 每次不同 | 统一模板 |
| 待办追踪 | 无负责人/截止日 | 自动提取并标注 |
| 决策追溯 | 容易遗漏 | 强制提取决策依据 |
| 风险预警 | 通常忽略 | 单独列出 |

## 不做什么

- 不实时记录会议（是事后整理）
- 不替代人工审核纪要准确性（建议复核）
- 不处理非文本格式的会议记录（需先转文字）
- 不自动发送纪要给参会人（需手动操作）

## 已知限制

- 超长会议记录（>5000字）可能遗漏细节
- 多语言混合的会议记录识别准确率较低
- 需要LLM模型支持（GPT-4/Claude级别）

## 依赖

- LLM模型：GPT-4 / Claude 3.5+ 级别
- 输入格式：纯文本（支持飞书妙记导出格式）
